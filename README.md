# BDEF 编解码工作台

> 把**中国剩余定理**用在字符编码上 —— 11 × 13 × 14 × 15 = 30030

一个完整的开源小项目：**网页版工具 + 桌面图形面板 + Excel 批量加解密 + 码书生成器**，
四种形态共用同一套算法与同一份码书，**字节级完全互通**。

* 🌐 在线使用：<https://chenzhuanxin.github.io/bdef-codec/>
* 💻 桌面面板：`python bdef_panel.py`
* 📊 Excel 批量处理：`python bdef_excel.py`
* 📚 码书生成：[`generate_codebook.py`](generate_codebook.py) + [`codebook.txt`](codebook.txt)

> ⚠️ **先读这一段**：基础编码与多对多模式**不是加密算法**，只是编码 / 混淆，
> 任何人都可能还原内容，**不能用于隐私、金融、军事或网络传输保密**。
> 真正需要保密时请使用 **AES 叠加模式**。详见 [安全声明](#安全声明)。

## 一、这个项目是什么

公众号文章《公歧子：BDEF编码法》提出了一种基于 **30030 字符表**的可逆编码方法：

给每个字符分配 `1 ~ 30030` 之间的唯一序号，加密时把序号分别除以 `11、13、14、15`
取余数，四个余数转成十六进制拼出 **4 位编码**，用 `-` 分组。它的数学基础是
**中国剩余定理**，所以编解码可逆、无歧义、实现极简。

原文给出了原理、Python 码书生成器和三代 HTML 实现（基础版 / 多对多版 / AES 版）。
本项目把原文的散落片段整理成一个**可直接运行的完整工程**，并做了几件原文没做的事：

| 本项目新增 | 说明 |
|---|---|
| 完整可复现的码书 | 原文 HTML 不含码书，需要自己生成后粘贴；本项目提供脚本 + 现成 `codebook.txt` |
| 码书覆盖完整 CJK 汉字 | 原文取前 15000 个汉字（到 U+8897），会漏掉不少繁体字；本项目覆盖 U+4E00–U+9FFF 全部 20992 个汉字 |
| 三方实现字节级互通 | 网页 (JS) / 桌面面板 (Python) / Excel 工具 (Python) 用同一算法，密文互解；附交叉验证脚本 |
| 纯标准库的 AES | Python 侧手写 AES-256-GCM，不依赖 `cryptography`，已通过 NIST 官方向量 |
| Excel 批量加解密 | 原文没有。整表加密 / 解密，自动跳过公式与合并单元格，AES 参数写入元信息表 |
| 桌面图形面板 | 原文只有网页版。tkinter 实现，零第三方依赖 |

## 二、算法原理

### 2.1 编码

```
序号 n (1 ≤ n ≤ 30030)
   ↓  分别对 11、13、14、15 取余
(r11, r13, r14, r15)        每个余数 = 1 个十六进制字符
   ↓  依次拼接
4 位编码，如 "1238"
   ↓  多个字符用 "-" 连接
密文，如 "1238-19a5-7549"
```

例：「一」的序号是 `1`
→ `1%11=1`、`1%13=1`、`1%14=1`、`1%15=1` → 密文 `1111`

### 2.2 为什么可逆

`11、13、14、15` **两两互质**，乘积恰好是 `30030`。由中国剩余定理，
任意 `0 ~ 30029` 的整数都被这四个余数**唯一确定**，于是与 `1 ~ 30030` 的字符编号
构成**双射**。解码时逐组还原余数、反解序号、查码书即可。

> 本项目对全部 **30030 个序号**都做过可逆性验证（见 `python bdef_core.py`）。

信息量：每字符 4 位十六进制 ≈ **14.87 bit**（理论 16 bit，冗余约 7%）。

### 2.3 三种增强手段

| 手段 | 做法 | 作用 |
|---|---|---|
| 密钥线性变换 | 密钥经 FNV-1a 哈希推出 `(a, b)`，`a` 与 30030 互质，做 `t = (a·chained + b) mod 30030`，可逆 | 没有密钥就还原不出序号 |
| 随机 IV + 链式混淆 | `chained = (n + prev) mod 30030`，`prev` 为上一字符的密文值，初始值为随机 IV | 同一明文每次密文都不同；前后字符相互影响 |
| 噪声组 | 以 0.30 的概率在数据组后插入 `~xxxx` | 打乱密文长度规律，干扰猜测 |

AES 模式则在全部上述编码之后，再套一层 **AES-256-GCM**：
密钥经 `PBKDF2-SHA256`（10 万次迭代）+ 随机盐派生，每次加密生成 16 字节盐 + 12 字节 IV，
输出 `Base64(盐 ‖ IV ‖ 密文 ‖ 认证标签)`。

## 三、三种模式对比

| 模式 | 是否需要密钥 | 机制 | 安全性 | 适用场景 |
|---|---|---|---|---|
| **基础编码** | 否 | 纯中国剩余定理编码 | ❌ 无。同一字符密文恒定，可频率分析，已知明密文对可直接反推码表 | 教学、趣味谜题、轻度混淆 |
| **多对多** | 是 | 密钥线性变换 + 随机 IV + 链式混淆 + 噪声组 | ⚠️ 弱。属于混淆，不是密码学加密 | 想让内容"一眼看不懂"的场合 |
| **AES 叠加** | 是 | 多对多编码 + AES-256-GCM / PBKDF2 | ✅ 强。安全性由 AES 提供，可检测篡改 | 真正需要保密的场景 |

三种模式的密文长这样：

```
基础编码   4442-19a5-7549-aa5a-1b28-1238-5422
多对多     aac8-726d-ac66-0583-~57b9-9371-92d4-...   （~ 开头的是噪声组）
AES 叠加   wk3cEeq6I7EpwwuMmp2xXfsBRMVWuiswBjxY...   （Base64）
```

## 五、快速开始

### 5.1 网页版（零安装）

**在线使用**：<https://chenzhuanxin.github.io/bdef-codec/>

**本地使用**：直接双击 `index.html`。

> 注意：AES 叠加模式需要浏览器提供 `crypto.subtle`，它只在 **HTTPS 或 localhost** 下可用。
> 因此用 `file://` 打开本地文件时 AES 模式不可用（页面状态栏会明确提示），
> 基础编码与多对多模式不受影响。想在本地用 AES，起一个本地服务器即可：

```bash
python -m http.server 8000
# 然后浏览器打开 http://localhost:8000/index.html
```

**界面功能**

| 区域 | 说明 |
|---|---|
| 编码模式 | 三种模式一键切换，下方实时显示该模式的机制说明 |
| 密钥 | 支持显示 / 隐藏、一键生成随机密钥（AES/多对多模式才启用） |
| 明文 / 密文 | 左右双栏，实时统计字符数与分组数；支持复制、清空、导出 TXT |
| 码书速查 | 输入字符反查编码 / 四位码 / Unicode / UTF-8 / 类别，输入编码反查字符 |
| 快捷键 | `Ctrl/⌘ + Enter` 执行（在明文区加密、在密文区解密），`Esc` 关闭提示 |

网页完全在浏览器本地运行，**不联网、不上传任何内容**。

### 5.2 桌面图形面板

```bash
python bdef_panel.py          # 打开图形界面
python bdef_panel.py --check  # 只跑核心自检，不开界面
```

界面分三个标签页：

* **🔒 加密** —— 输入明文，选模式、填密钥，点「加密 →」，结果可直接复制或保存为文件
* **🔓 解密** —— 粘贴密文，点「← 解密」；「送入解密页 / 送回加密页」可以一键互传，方便自测
* **🔍 码书速查** —— 字符 ↔ 编码互查

模式说明会随选择实时变化；如果明文里含码书未收录的字符（如 emoji），
底部状态栏会用橙色明确提示跳过了哪些字符。

### 5.3 Excel 批量加解密

#### 第 1 步：拿到模板

模板已经在仓库里：[`templates/BDEF_excel_template.xlsx`](templates/BDEF_excel_template.xlsx)
（含「使用说明」页和一份示例数据）。也可以随时重新生成：

```bash
python bdef_excel.py template -o my_template.xlsx
```

#### 第 2 步：图形界面（推荐）

```bash
python bdef_excel.py
```

操作流程：

1. 选择**输入文件**（`.xlsx` / `.xlsm`）。工具会自动识别它是不是 BDEF 加密过的文件。
2. 选模式、填密钥（AES / 多对多必填）。
3. 勾选选项：是否跳过首行表头、解密后是否把纯数字还原为数值。
4. 点「🔒 加密」或「🔓 解密」，完成后会提示处理了多少个单元格。

#### 第 3 步：命令行（适合批处理 / 脚本）

```bash
# 加密（AES 模式，推荐）
python bdef_excel.py encrypt -i 员工信息.xlsx -o 员工信息_加密.xlsx -k "你的密钥" -m aes

# 解密
python bdef_excel.py decrypt -i 员工信息_加密.xlsx -o 员工信息_还原.xlsx -k "你的密钥" -m aes

# 其它模式
python bdef_excel.py encrypt -i a.xlsx -o b.xlsx -m basic          # 基础编码（无密钥）
python bdef_excel.py encrypt -i a.xlsx -o b.xlsx -k kk -m multi    # 多对多

# 只处理指定列
python bdef_excel.py encrypt -i a.xlsx -o b.xlsx -k kk -m aes -c B,C,D

# 自检：用临时文件跑一遍三种模式的往返，验证数据无损
python bdef_excel.py selftest
```

#### 处理规则（重要）

* 只处理**有值**的单元格。空单元格、公式单元格、合并单元格的从属格会自动跳过。
* 处理过的单元格统一设为**文本格式**，避免 Excel 把密文当数字或公式。
* **AES 模式会在工作簿里新增一张 `_BDEF_META` 表**保存盐值与参数，
  请勿删除或改名 —— 解密时需要它。解密完成后该表会被自动移除。
* **数字类型保护**：解密时只有"安全"的纯数字才会还原成数值，即
  没有前导零、且整数部分不超过 15 位。像身份证号（18 位）、长银行卡号
  这类会**原样保持文本**，避免转成浮点数后精度丢失。
  可用 `--no-restore-number` 完全关闭还原。
* 输出文件不能与输入文件同名（工具会拦下来）。

## 六、跨语言互通与自检

### 6.1 三个自检

```bash
python bdef_aes.py    # AES-256-GCM 正确性（NIST/GCM 官方测试向量 + 篡改检测）
python bdef_core.py   # 30030 个序号全部可逆 + 三种模式往返 + 缺失字符处理
python bdef_excel.py selftest   # Excel 三种模式往返 + 长数字保护 + 错误密钥拒绝
```

### 6.2 跨语言一致性（Python ↔ JavaScript）

```bash
node tools/cross_check.js        # 1. JS 端产出比对数据
python tools/cross_check.py      # 2. Python 端比对 + 反向触发 JS 验证
```

验证内容包括：

1. 30030 个序号的四位编码逐一对齐
2. 同一密钥派生的 `(a, b)` 完全一致
3. **同一确定性随机源下**，多对多密文（含 `~` 噪声组）逐字符相同
4. JS 加密的 AES 密文能被 Python 解开，Python 加密的能被 JS 解开

实测结果：

```
[1] 编码表 30030 条对齐：通过
[2] 密钥派生 4 组对齐：通过
[3] 多对多密文逐字符一致 + Python 可解 JS 密文：通过
[4a] Python 解开 JS 的 AES 密文：通过
[4b] 已写出 Python 的 AES 密文，等待 JS 端反向验证
[5] Python 解开 JS 的多对多密文：通过
[6a] JS 解开 Python 的 AES 密文：通过
[6b] JS 与 Python 的多对多密文逐字符一致：通过

交叉验证结果：全部通过 ✅  两套实现字节级一致
```

所以你可以：**在网页上加密 → 用 Python 面板解密 → 用 Excel 工具批量还原**，
全程无需格式转换。

## 七、码书说明

码书共 **30030** 条，按下面的顺序收录字符：

| 顺序 | 类别 | 数量 | 说明 |
|---|---|---|---|
| 1 | 常用中文字 | 20992 | `U+4E00 ~ U+9FFF`，**完整 CJK 统一汉字区，简体繁体全覆盖** |
| 2 | 英文字母 / ASCII / 拉丁扩展 | 638 | 大小写字母、可打印 ASCII、拉丁补充与扩展 A/B、组合附加符号 |
| 3 | 日文 | 248 | 平假名、片假名、半角片假名 |
| 4 | 标点 | 248 | 中文标点、全角符号、通用标点 |
| 5 | 符号 | 891 | 上下标、货币、箭头、数学运算符、几何图形、装饰符号、带圈字符 |
| 6 | 希腊 / 西里尔 | 391 | 希腊字母、俄文字母 |
| 7 | 韩文 | 11522 + 填充 | 谚文字母、兼容字母、韩文音节 |
| 8 | 泰文 / 越南文 | 343 | 泰文、拉丁扩展附加 |

开头 10 条与原文一致：`一 丁 丂 七 丄 丅 丆 万 丈 三`。

**没有收录**：emoji、CJK 扩展 B 区（`U+20000` 以上的生僻字）等。
遇到这些字符时各工具都会**明确提示并跳过**，不会静默丢数据。

> 原文的汉字区取前 15000 个（到 `U+8897`），会漏掉「語、龍、龜」这类常用繁体字。
> 本项目把汉字区扩到完整的 `U+4E00 ~ U+9FFF`，编码 `1 ~ 15000` 与原文完全相同，
> 之后的编码顺序与原文不同（原文未公开其精确算法，无法逐条复现）。
> 需要原文口径时运行 `python generate_codebook.py --hanzi-count 15000`。

## 八、常见问题

**Q：网页版用 `file://` 打开，AES 模式是灰的？**
A：`crypto.subtle` 只在安全上下文（HTTPS / localhost）可用。用
`python -m http.server 8000` 起个本地服务再访问 `http://localhost:8000/index.html` 即可。

**Q：解密报「认证标签校验失败」？**
A：AES 模式特有的错误。说明密钥不对，或者密文被改动过（AES-GCM 自带防篡改）。

**Q：多对多模式用错密钥，为什么有时候不报错？**
A：多对多不是密码学加密。用错密钥解出来的序号**可能**恰好落在合法范围内，
于是会被"成功"解成一段乱码而不是报错。要可靠地发现密钥错误，请用 AES 模式。

**Q：加密后 Excel 单元格变得很长，列宽被改了？**
A：密文确实比原文长（基础模式约 5 倍）。工具会把涉及到的列宽设为 38（加密）/ 18（解密）方便查看，
不影响数据本身。

**Q：能在不装 Python 的电脑上解密吗？**
A：可以。直接用网页版，或在任何机器上打开 GitHub Pages 的在线版本。

**Q：密钥丢了怎么办？**
A：多对多与 AES 模式的数据**无法恢复**。这是设计使然，请务必妥善保管密钥。

## 九、安全声明

本项目是**教学与趣味实践**项目，请务必了解它的边界：

1. **基础编码、多对多都不是加密算法**，只是编码 / 混淆。
   * 基础编码：同一字符密文恒定 → 可频率分析；已知明密文对可直接反推码表。
   * 多对多：密钥变换是模 30030 的线性映射，噪声组只是干扰，都经不起专业密码分析。
2. 上述两种模式下，**密文长度直接暴露明文长度**（多对多靠噪声组部分掩盖）。
3. 只有 **AES 叠加模式**具备实际保密能力，其安全性完全来自 AES-256-GCM + PBKDF2，
   BDEF 在其中只扮演混淆层。
4. 真实保密需求，建议直接使用标准方案：**AES-GCM** 或 **ChaCha20-Poly1305**
   （例如 `cryptography` 库 / 操作系统自带的加密工具）。
5. 本项目不收集、不上传任何数据；网页版全程在浏览器本地运行。
