📖 算法原理、安全性与使用说明

1. 它到底做了什么

码书给每个字符分配一个 1 ~ 30030 的唯一序号 n。加密时把 n 分别对 11、13、14、15 取余，得到四个余数，各转成一个十六进制字符， 拼成 4 位编码，用 - 分组。

例如「一」的序号是 1：1 % 11 = 1、1 % 13 = 1、1 % 14 = 1、1 % 15 = 1 → 密文 1111。

2. 为什么可逆 —— 中国剩余定理

11、13、14、15 两两互质，乘积正好是 30030。按中国剩余定理，任意 0 ~ 30029 的整数都能被 这四个余数唯一确定，于是与 1 ~ 30030 的字符编号形成一一对应（双射）。解码时逐组还原余数、 用中国剩余定理反解序号、再查码书即可。本项目已对 30030 个序号全部做过可逆性验证。

每字符用 4 位十六进制承载，约 14.87 bit；理论空间 16 bit，冗余约 7%。

3. 三种模式对比

模式机制安全性
基础编码纯中国剩余定理编码，无密钥无。同一字符密文恒定，可频率分析、可直接反推码表
多对多密钥派生 (a,b) 做模 30030 可逆线性变换 + 随机 IV + 链式混淆 + ~ 噪声组弱。属于混淆而非密码学加密，只提高门槛
AES 叠加先做多对多编码，再套 AES-256-GCM（PBKDF2-SHA256，10 万次迭代，随机盐 16B + IV 12B，整体 Base64）强。安全性由 AES 提供，可抵御已知明文攻击、可检测篡改

4. ⚠️ 必须知道的安全边界

  • 基础模式与多对多模式都不是加密算法，只是编码 / 混淆，不能用于隐私、金融、军事或网络传输保密。
  • 真正需要保密时请使用 AES 叠加模式。AES 模式需要通过 HTTPS 或 localhost 打开页面，否则浏览器不提供 crypto.subtle。
  • 码书中没有的字符（例如 emoji、极生僻字）会被跳过，界面上会明确提示，请自行核对。
  • 密钥一旦丢失，多对多与 AES 模式的数据无法恢复。

5. 快捷键与离线使用

  • Ctrl / ⌘ + Enter：在明文区执行加密，在密文区执行解密。Esc 关闭提示条。
  • 本页面完全在浏览器本地运行，不联网、不上传任何内容。
  • 码书由同目录的 codebook.js 提供（用 generate_codebook.py 生成），当前共 30030 条。
  • 与项目内的 Python 工具（bdef_core.py / bdef_panel.py / bdef_excel.py） 字节级互通：网页加密的数据可以用 Python 解密，反之亦然。
